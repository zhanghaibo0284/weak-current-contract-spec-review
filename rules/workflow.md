## 10. 审查流程

### 10.1 六步标准流程

| 步骤 | 名称 | 输入 | 动作 | 输出 |
|---|---|---|---|---|
| 1 | 建基线 | 合同/规格书/清单 | 记录材料版本；提取车站数 N、冗余层级 R、点数 P、链路数 L、并发 C、供电分区等基线 | 项目基线表 + 材料清单 |
| 2 | 数量配比校验 | 基线 + 设备材料表 | 按 16 条配比以驱动因子×系数核算理论量，比对清单量，偏差>5% 登记待核验 | 数量核对表 |
| 3 | 参数—场景匹配 | 规格书 + 参数检查项 | 逐设备写场景→反推能力→核参数，按 63 条逐项核对 | 参数核实结果 |
| 4 | 交叉匹配 | 上述结果 | 执行 `rules/cross-checks.md` 交叉检查，核对 OS×硬件、协议×对端、接口×线缆等 | 兼容性冲突清单 |
| 5 | 证据核验 | 彩页/报告/书面证明 | 核对测量口径、证据覆盖型号、替代认定与换型审批 | 证据清单 + 待核验项 |
| 6 | 登记与分级 | 全部命中项 | 按 `rules/severity.md` 分级，套用 `templates/issue-list-template.md` 模板，指定主责与闭环时限 | 结构化问题清单 + 覆盖台账 + 评审报告 + 澄清问题单 |

### 10.2 单项判定逻辑

```text
对每一检查项：
  读取对应条款/材料原文
  if 材料缺失或不可判定: 结论=待核验, 记录需补充材料
  elif 命中异常判定信号: 结论=存在风险, 按 rules/severity.md 定级, 生成问题条目
  elif 明确不适用并注明理由: 结论=不适用
  else: 结论=符合
  所有命中项保留原文片段与定位信息（召回优先，不自动删除）
  无论结论为何，均须在覆盖台账中占一行（见 templates/coverage-ledger.md）
```

### 10.3 角色与分工（可配置）

| 角色简称 | 角色 | 核心职责 |
|---|---|---|
| PM | 资深项目经理 | 统筹合同范围内外部界面、进度、资源与风险闭环；对范围、责任、变更、工期、罚则、移交、兜底条款负总责 |
| TE | 技术总工 | 对技术方案可实现性、参数、接口、软件架构、清单闭合、验收技术判据负责 |
| CM | 商务经理 | 对价格口径、变更计价、罚则、付款结算、澄清与谈判纪要的商务后果负责 |
| PR | 采购/供应链经理 | 对供方认定、品牌型号可得性、长周期件、备品备件、采购合同背靠背负责 |
| QA | 质量/测试经理 | 对认证合规、检验检测、厂验与全链条验收判据、质量体系负责 |
| LG | 法务/合规 | 对文件效力、责任上限、知识产权、争议解决、保险与条款合法性负责 |
| OM | 交付/运维经理 | 对质保、售后响应、培训、图纸文档、移交与尾工闭环负责 |
| FI | 财务/成本经理 | 对成本测算、取费口径、不可预见费、税负、现金流与回款负责 |

> 角色重点类别映射见附录 A；高风险类别建议双人交叉复核。

### 10.4 复核与闭环

1. 每条问题项标注责任人建议与完成时限；高等级项须在合同谈判/澄清阶段形成书面结论。
2. 未闭环的高风险项不得进入详细设计与批量采购。
3. 澄清结果、业主答复与最终决策回填台账，保留版本与闭环记录（对应 RISK-R05）。

### 10.5 异常处理与降级（执行前必读）

执行主体在任一步骤遇到下述情形时，**不得静默跳过，也不得臆测补全**，按下表处置并在报告「解析质量声明」中留痕。

| 异常码 | 情形 | 处置（阻断级别） | 必附提示语 |
|---|---|---|---|
| E-01 | 文件无法打开/加密/损坏 | **阻断**：该材料整体标记「不可读」，其相关检查项全部结论=待核验 | 「文件《X》无法解析，已标记不可读；以下结论依赖该文件，均为待核验。」 |
| E-02 | 扫描件无文本层 | **降级**：启用 OCR；OCR 置信度低的段落不得用于数值判定 | 「《X》为扫描件，已 OCR；页码与数值可能存在识别误差，请以原件复核。」 |
| E-03 | 表格含合并单元格/公式/隐藏行 | **降级**：读取计算值并标注；无法解析的列标记「未读取」 | 「表《X》第 N 列含公式/合并单元格，已按显示值读取，请核对原始口径。」 |
| E-04 | 多册/多版本并存且未声明以何为准 | **阻断该项**：按 RISK-A02 登记高风险，版本问题未澄清前不做跨文件数值比对 | 「存在版本冲突：A 版与 B 版；未确认以何者为准，相关比对结论为待核验。」 |
| E-05 | 图纸/影像等非文本证据 | **降级**：仅按图签、说明文字核对，不做图形量算 | 「图纸仅按文字说明核对，未做尺寸/数量量算。」 |
| E-06 | 关键结论依赖外部知识（如 CPU 支持列表）且无书面证据 | **降级**：结论=待核验，列入澄清问题单 | 「该项需厂家书面证明或官方支持列表确认，当前仅列核对要点。」 |
| E-07 | 材料齐备度低于门槛（见 `rules/inputs.md` 5.4） | **阻断全量审查**：只输出材料缺口清单与已具备部分的有限结论 | 「必需材料缺 N 项，暂不进行全量逐条判定，详见材料缺口清单。」 |

> 原则：宁可少判，不可错判；任何降级都必须在输出中显式声明，禁止把「未读到」写成「不存在」。

### 10.6 状态机与增量复核

问题条目在生命周期内维护 `状态`，取值与迁移如下（字段定义见 `templates/output-schema.json` 扩展字段）：

```text
待澄清 --(收到书面答复)--> 已澄清 --(整改或接受)--> 已关闭
   |                          |
   +--(判定为误报)-----------> 放弃
```

1. **状态为 `已关闭` / `放弃` 的条目不得删除**，只改状态并记录 `关闭依据`，保留召回优先的审计痕迹。
2. **增量复核**：收到澄清/补遗/新版本规格书时，先产出「版本差异登记表」（`templates/rfi-list.md` 附表），标出受影响规则编号；仅重跑受影响规则，未受影响条目的 `问题编号` 保持不变。
3. **问题编号稳定性**：同一事实在多次复核中沿用同一 `问题编号`；若事实变更，新增条目并在 `判定依据` 中注明「替代 CSR-00X」。
4. 覆盖台账须随之更新 `规则版本` 与 `复核时间`，保证报告与台账版本一致。

## 11. 确定性执行与运行清单（DET / CON）

六步流程本身不变；本节规定每一步之上的"可复现约束"，任何一条不满足即不得发布产物。

### 11.1 参数轴（进入流程前）

| 参数 | 取值 | 说明 |
|---|---|---|
| `stance` | seller / gc / owner / supervisor | 同一 ★ 条款在不同立场下结论相反，必须显式声明 |
| `profile` | quick / standard / verify | 决定规则子集 |
| `recall` | wide / standard / narrow | 默认 wide |
| `review_date` | `YYYY-MM-DD` | 唯一时间来源，禁止系统时钟 |
| `rule_version` | 语义版本 | 与规则集指纹绑定 |
| `locale` | zh-CN | 数字与日期格式 |

缺任一参数即失败，禁止默认值填充（异常码 E-09）。

### 11.2 坐标与编号

1. 正文按块坐标 `B00001` 定位，表格按 `T001:R01:C01` 定位，不使用页码；
2. 问题编号 = `ISSUE-<规则编号>-<证据坐标 SHA-256 前 8 位>`，与调用顺序、并发数无关；
3. 排序键 = 等级 → 位置 → 编号 → 描述哈希，保证全序。

### 11.3 运行清单

每次运行在输出目录写 `run_manifest.json`，字段见 `templates/run-manifest.schema.json`：
`input_hash`、`params_hash`、`ruleset_checksum`、`output_hash`、`review_date`、`stance`、`profile`。
产物目录按内容寻址：`out/<input_hash 前12位>/<params_hash 前12位>/`。

### 11.4 发布前强制校验

1. C1 7 字段与枚举；C2 台账 187 条无缺无多；C3 规则引用可解析；C4 问题与台账互证；C5 `output_hash` 重算一致；
2. 同一输入连跑两次，产物逐字节一致；不一致阻断并保留差异报告；
3. 命令行复核：`python verify_skill.py --run <输出目录>`。

### 11.5 进化边界

只允许改 `rules/config.json` 中的阈值、召回档与 quick 档子集（A 类，单人审批）；维度归属、升级条件、分支映射属 B 类，需双人审批与灰度，本版本不开放自动发布；规则文本、7 字段、六步顺序、编号命名空间属 C 类，禁止自动进化。

A 类提案须通过"5 次确定性复跑、召回不降、误报增幅 ≤2 个百分点、覆盖 =187、耗时 ≤1.2 倍"五道门，并在 `evolve/golden/` 黄金集上回测；发布先写 `versions/shadow/<版本>/`，验证通过后切换 `versions/current.json`，可用 `guard/evolve_cli.py rollback` 回滚。详见 `guard/evolve.py`、`guard/golden.py`、`guard/versions.py` 与 `evolve/README.md`。
