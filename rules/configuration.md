## 12. 配置化与平台中立复用约定

### 12.1 可配置项（外置，不写死在流程里）

| 配置项 | 默认值 | 说明 |
|---|---|---|
| 数量偏差阈值 | 5% | `thresholds.quantity_deviation_pct`；超过即登记待核验，可按项目调整 |
| 参数余量区间 | 10%~20% | `thresholds.parameter_margin_pct`；I/O 模块、存储等设计余量基线 |
| 运行时余量区间 | 20%~30% | `thresholds.runtime_headroom_pct`；内存等按并发应用估算的余量 |
| 每页段落/字符阈值 | 40 段 / 1200 字 | `thresholds.page_estimate_*`；仅用于页码估算，非精确定位 |
| 灵敏度档位 | 宽 / 标准 / 窄 | 宽=召回优先，窄=精确短语；默认宽 |
| 审查档位 | quick / standard / verify | 控制审查范围（规则子集），与灵敏度档位正交 |
| 审查立场 | seller / gc / owner / supervisor | 决定条款被解读为「风险」还是「保护」，默认 seller |
| 问题状态 | 待澄清 / 已澄清 / 已关闭 / 放弃 | 闭环台账状态机，见 `rules/workflow.md` 10.6 |
| 置信度 | 确认 / 疑似 / 线索 | 与风险等级正交，用于人工剔除排序 |
| 风险等级词表 | 高/中(待核验)/低/不适用 | 可映射为其他分级体系 |
| 维度编号与名称 | DIM-01~DIM-12 | 可对映到组织内部审查分类 |
| 角色与职责 | 8 类（PM/TE/CM/PR/QA/LG/OM/FI） | 可替换为实际岗位 |
| 输出字段 | 7 字段 | 可扩展但不可删减 |

### 12.2 规则外置数据结构（平台中立 schema）

规则以通用数据表（如 JSON / CSV / 表格）外置，字段建议：

```json
{
  "rule_id": "C01",
  "dimension": "DIM-01",
  "category": "C",
  "check_point": "检查要点（问句）",
  "signal": "异常判定信号（命中即疑似风险）",
  "evidence_source": "证据来源（文档定位）",
  "method": "核查方法与处置建议",
  "level": "高|中|低",
  "owner": "主责角色",
  "co_owner": "协同角色",
  "sensitivity": ["wide","standard","narrow"],
  "enabled": true
}
```

三类规则共用此结构：合同风险规则（108）、数量配比规则（16）、参数核实规则（63），
以 `rule_type` 区分。修改规则后重载即生效，无需改动流程逻辑。

### 12.3 平台中立接入约定

1. **能力即数据与流程**：本能力以「规则数据 + 判定流程 + 输出模板」三件套定义，与实现技术解耦。
2. **基础能力要求**：执行主体只需具备文本检索（关键词/正则）、表格读取、结构化输出三类基础能力。
3. **可替换性**：文档解析（Word/PDF）、表格处理、报告生成、标注高亮等均可由任意工具实现；本说明不指定实现方式。
4. **召回优先**：筛查阶段允许误报，不做否定式排除；误报剔除由人工在输出台账完成，能力本身不自动删除命中项。
5. **可追溯**：规则版本、材料版本、判定依据一并记录，支持复核与审计。
6. **移植步骤**：复制规则数据 → 按 `rules/configuration.md` 配置阈值/词表/角色 → 实现 `rules/workflow.md` 流程 → 按 `templates/issue-list-template.md` 输出 → 用样例回测召回率。
