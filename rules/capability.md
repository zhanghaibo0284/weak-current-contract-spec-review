| 项    | 内容                                                                        |

| 能力编号 | CAP-CSR-001                                                               |
| 版本   | 1.0.0                                                                     |

### 1.1 能力定位

本能力把「合同/技术规格书审查」从依赖个人经验的通读，转化为**可逐条核对、可定位证据、可判定等级、可闭环跟踪**的标准化流程。  
它在三个层次上工作：

1. **合同风险识别**——从合同正文与技术规格书中识别开口责任、兜底条款、界面空白、验收陷阱、罚则与付款风险等。
2. **参数合规与场景匹配**——不只核对参数数值，还结合设备在项目中的作用，反推所需能力，核对参数—场景—配套件是否匹配。
3. **数量配比自洽**——以车站数、冗余层级、点数、链路数等驱动因子核算理论量，与清单量比对，识别比例异常。

> 核心判断：参数与数量的异常，往往不是「某个数字写错」，而是「关系错」——设备间比例不对、参数与用途不对、软件与硬件不对、接口与线缆不对。发现异常时优先怀疑口径、冗余层级或漏项，而非直接判定为笔误。

## 2. 适用场景

### 2.1 行业与项目类型

适用于弱电/智能化/机电集成类项目，典型包括：

- 城市轨道交通：综合监控（ISCS）、环境与设备监控（BAS）、门禁安防、视频监控、乘客服务、能源管理、智慧车站平台、无线定位、车场管理；
- 铁路、市政、数据中心、园区、大型公共建筑的弱电智能化与信息化集成项目；
- 以 Word/PDF 技术规格书 + Excel 设备材料表/报价册 + 合同正文为主要交付依据的工程承包与设备供货项目。

### 2.2 使用阶段

| 阶段      | 使用方式                             |
| ------- | -------------------------------- |
| 售前/投标   | 对照招标技术规格书与清单，识别开口条款与漏项，支撑澄清与报价决策 |
| 合同谈判/交底 | 逐条核对合同与技术规格书，形成澄清问题清单与谈判要点       |
| 设计联络    | 核对「待设计联络确定」事项，建立基线，防止范围扩张        |
| 到货/验收前  | 复核参数证据、数量配比、验收判据，降低不通过风险         |
| 项目复盘    | 作为风险台账与审计追溯的标准化底稿                |

### 2.3 不适用场景

- 纯软件产品研发、无合同/技术规格书载体的项目；
- 需要对条款法律效力、**合规性结论**或争议责任作**定性判定**的场景（本能力仅提供线索，不构成法律意见）；
- 无设备清单、无量化参数的纯服务类合同（本能力多数检查项将判为「不适用」）。

## 3. 触发条件

当满足以下**任一**条件时，应启动本能力：

1. **材料触发**：收到新的合同草案、技术规格书（Word/PDF）、设备材料表或报价册，需要评审。
2. **节点触发**：进入合同交底、设计联络会、首批到货、厂验、完工测试、预验收等关键节点前的准备阶段。
3. **变更触发**：收到澄清、补遗、谈判纪要、业主需求调整或规格书版本变更，需重新评估风险。
4. **异常触发**：发现数量比例明显异常、参数与使用场景冲突、OS×硬件不兼容、证据缺失等信号。
5. **复核触发**：项目例会对高风险项、待核验项进行交叉复核或闭环检查。

触发后先执行 `rules/inputs.md` 的输入材料齐备性检查；材料不齐时按「待核验」登记，不以「不存在」结论替代。

## 4. 审查目标

| 编号 | 目标    | 可度量判据                                   |
| -- | ----- | --------------------------------------- |
| G1 | 风险无遗漏 | 108 条合同风险检查项逐条给出结论（符合/存在风险/待核验/不适用），无空白 |
| G2 | 参数可用  | 63 条参数核实项覆盖所有关键设备，含场景—能力—参数—配套件的匹配判断    |
| G3 | 数量自洽  | 16 类设备按驱动因子核算理论量，偏差项均登记并标注口径            |
| G4 | 证据可追溯 | 每条问题均给出「对应条款或材料位置」与「判定依据」，可在原文定位        |
| G5 | 分级可决策 | 每条问题给出风险等级与处置建议，高等级项有闭环路径与责任人建议         |
| G6 | 输出标准化 | 全部问题落入 `templates/issue-list-template.md` 的 7 字段模板，可直接汇总为台账与评审报告       |

### 12.3 平台中立接入约定

1. **能力即数据与流程**：本能力以「规则数据 + 判定流程 + 输出模板」三件套定义，与实现技术解耦。
2. **基础能力要求**：执行主体只需具备文本检索（关键词/正则）、表格读取、结构化输出三类基础能力。
3. **可替换性**：文档解析（Word/PDF）、表格处理、报告生成、标注高亮等均可由任意工具实现；本说明不指定实现方式。
4. **召回优先**：筛查阶段允许误报，不做否定式排除；误报剔除由人工在输出台账完成，能力本身不自动删除命中项。
5. **可追溯**：规则版本、材料版本、判定依据一并记录，支持复核与审计。
6. **移植步骤**：复制规则数据 → 按 `rules/configuration.md` 配置阈值/词表/角色 → 实现 `rules/workflow.md` 流程 → 按 `templates/issue-list-template.md` 输出 → 用样例回测召回率。
