## 9. 常见问题判定依据

### 9.1 六类异常的统一判定与处置

| 异常类型 | 判定信号 | 处置动作 | 升级条件 |
|---|---|---|---|
| 数量 / 比例异常 | 清单量与「驱动因子×系数」理论量偏差 >5%，或出现 2N/4N 等比例明显不符 | 先排查漏配、重复计列、冗余层级理解不同、计量口径不一致，再定性；发澄清问题并测算最不利量。 | 涉及开口条款（遗漏免费补齐、总价不变）或影响可用性/验收 → 升级为高风险 |
| 参数低于使用场景需求 | 设备在项目中的作用所需能力高于清单参数（如三维场景与显卡） | 写清场景→反推能力→核对型号与基准；同步核对配套件与报价联动。 | 导致功能无法实现或验收不通过 → 升级为高风险 |
| 兼容性 / 匹配冲突 | OS×CPU/固件、协议×对端、接口×线缆、显卡×多屏、许可数×虚机数不一致 | 做交叉匹配矩阵，取得厂家书面兼容确认；必要时启动型号变更审批。 | 换型触发「不得改变型号品牌」或影响工期/等保 → 升级为高风险 |
| 参数不可验证 | 指标无测试工况、无测量方法、无验收判据 | 补齐「测试环境—负载—测量方法—记录表—通过判据」，写入澄清问题。 | 指标为 ★ 或影响验收/罚则 → 升级为高 |
| 证据缺失 / 型号不符 | 彩页、检测报告、CCC、兼容性证明缺失，或覆盖型号与投标型号不一致 | 建立证据清单，逐项取得并核对有效期；未取得前标记「待核验」。 | 涉及强制认证或进场条件 → 升级为高风险 |
| 联动漏项 | 参数调整后未同步更新数量、配套件、软件许可、电源与报价 | 建立参数—数量—配套件—许可联动检查表，每次变更后回查一遍。 | 被兜底条款覆盖、需免费补齐 → 至少中风险，累计金额大时升级 |

### 9.2 典型综合案例（判定范式）

以下案例演示从「表述 → 核查步骤 → 发现 → 后果 → 处置」的完整判定链，可作为同类问题的判定范式。

#### 案例 1　设备间比例异常：10 座车站的冗余 PLC

| 项 | 内容 |
|---|---|
| 场景 | 项目规模 N=10 座车站，采用车站 A/B 两端冗余 PLC 架构；清单列冗余 PLC 控制器 12 套。 |
| 规格书/清单表述 | 规格书写「车站 A/B 端冗余 PLC 控制器」「投标人应合理布置通信接口并按现场实际提供」；设备材料表数量栏为 12 套，另在备注中出现「冗余配置」。 |
| 核查步骤 | ① 确认冗余层级：是每站 A/B 两端各 1 套（2N=20），还是每端再双机热备（4N=40）；② 确认「套」的计量口径（整套机架 / 仅 CPU 模块 / 含 I/O 从站）；③ 按 2N、4N 分别算理论量并与 12 比对；④ 排查是否重复计列或把部分设备并入其他清单项；⑤ 回查车辆段、中心、培训系统是否另计。 |
| 发现 | 12 套与 20/40 套的经验基线明显不符，且备注出现「冗余配置」而数量未按冗余倍数放大 → 高度疑似漏配或口径不一致，而非简单笔误。 |
| 后果 | 详设阶段被援引「遗漏据实补齐、合同总价不变」免费补足；或冗余层级不达标导致可用性指标与验收不通过。 |
| 处置 | 发正式澄清：请明确冗余层级、计量口径与理论配置表；在澄清前按 4N 上限测算最不利成本并列入不可预见费；同步核对 I/O 模块、通信接口与光电转换器数量是否随之变化。 |

#### 案例 2　参数—场景匹配：三维展示工作站的显卡与多屏接口

| 项 | 内容 |
|---|---|
| 场景 | 控制中心/车控室工作站需展示三维场景与 BIM 模型，并同时驱动 55 寸触摸屏与带鱼屏。 |
| 规格书/清单表述 | 清单：触摸屏工作站显卡标配 8G 显存；IBP 盘管理工作站显卡为 4G 显存；带鱼屏只配 1 根接口线缆；触摸屏到工作站的 HDMI 线缆未列。 |
| 核查步骤 | ① 先写场景：三维渲染 + 多屏输出 + 触摸交互；② 由场景反推能力：GPU 算力/显存需满足模型规模与分辨率，需支持软件所需 OpenGL/DirectX 版本；③ 核对显卡具体型号与基准，对比 8G 与 4G 的差异是否影响同一软件；④ 数显示器数量→核对工作站视频输出接口数与类型（HDMI/DP）、是否需转换器、线缆数量与长度；⑤ 核对触摸 USB 驱动在该 OS 下兼容；⑥ 把线缆、转换器、可能的显卡升级联动到报价与电源配置。 |
| 发现 | 4G 显存工作站可能无法流畅运行三维场景；带鱼屏 1 根线缆无法连接 2 台工作站；若接口为 1 HDMI + 1 DP 还需 DP 转换器；缺 2 条 ≥2.5 m HDMI 线与触摸 USB 线。 |
| 后果 | 被援引「系统完整性由卖方完全负责 / 未纳入报价由卖方负责」免费补齐；联调阶段发现画面卡顿或无法点亮，影响预验收。 |
| 处置 | 形成澄清问题清单（显卡最低型号与显存、接口数量、2K 输出能力、线缆与转换器归属）；同步核算升级显卡后的电源/散热与报价联动；对无法改约项计入成本预留。 |

#### 案例 3　兼容性冲突：招标要求 Win11 但工作站 CPU 为 8 代平台

| 项 | 内容 |
|---|---|
| 场景 | 招标文件/技术规格书要求工作站操作系统为 Windows 11；投标清单中工作站采用第 8 代（或更早）工控 CPU 平台。 |
| 规格书/清单表述 | 规格书：「工作站操作系统为 Windows 11」「卖方提供所有软件许可证」；清单：工作站 CPU 型号为第 8 代工控处理器，主板未标注 TPM 2.0 / UEFI。 |
| 核查步骤 | ① 不只看代际，查微软官方 Windows 11 支持的 CPU 具体型号列表（Intel 约第 8 代及以后、AMD Ryzen 2000 及以后，须以具体型号为准）；② 核对主板是否具备并可启用 TPM 2.0（或 fTPM/PTT）；③ 核对 UEFI + Secure Boot、内存 ≥4GB、存储 ≥64GB、显卡支持 WDDM 2.0；④ 核对业务软件、组态软件、触摸屏驱动是否有 Win11 版本；⑤ 若不匹配，评估换型方案与「未经买方允许不得改变型号、品牌」审批流程；⑥ 同步核对 License 数量与等保加固要求。 |
| 发现 | 若 CPU 为 8 代以前、或虽为 8 代但型号不在支持列表、或主板无 TPM 2.0/UEFI，则 OS 与硬件明显不匹配；即使 CPU 勉强达标，工控主板缺 TPM 2.0 同样无法安装。注意：8 代不等于一定兼容，必须核对具体型号与固件。 |
| 后果 | 无法安装或无法获得厂商支持，等保漏扫与验收受阻；换型需买方审批，触发「不得改变型号品牌」条款，可能连带改动驱动、License 与报价，并影响供货周期。 |
| 处置 | 请业主/监理书面确认 OS 版本与是否接受替代方案；取得工作站厂家出具的 Win11 兼容性证明（含 CPU 型号、TPM 2.0、驱动清单）；如需换型，提前启动型号变更审批并同步调整报价与工期基线。 |

### 9.3 高频风险话术速查（召回优先词表）

命中以下话术即应登记为疑似风险线索，逐条测算潜在工作量与金额，不做否定式排除（否定句本身常是风险条款）：

| 风险族 | 典型话术/信号词 | 对应检查项（带规则集前缀） |
|---|---|---|
| 开口工程量 | 仅供报价参考、买方对数量不负责任、以详细设计为准、遗漏据实补齐、合同总价不变 | RISK-A03, RISK-A04, RISK-D01, RISK-I04 |
| 免费补足 | 免费提供、免费增加、免费补足、无偿、不另计费、不予补偿、已含在总价 | RISK-D03, RISK-D06, RISK-I01 |
| 兜底与总责 | ★、最低要求、基本要求、包括但不限于、负总责、负全部责任、不减轻责任 | RISK-A03, RISK-P02, RISK-T01, RISK-T02 |
| 免费研发/升级 | 二次开发、方案优化、科技创新、软硬件升级、配合研究、不得提出额外要求 | RISK-F05, RISK-I03 |
| 单方裁量 | 以买方解释为准、买方认为有必要时、最终要求由用户确认、买方裁决 | RISK-T05, RISK-B05 |
| 不可索赔 | 不得以任何理由提出增加费用或延长工期、不得索赔 | RISK-T03, RISK-B05, RISK-I02 |
| 长期原价供货 | 质保期后3年、单价不得高于报价册、种类和数量可调、免费补足备件 | RISK-D04, RISK-L02, PARAM-P58 |
| 源码与IP | 知识产权归买方所有、提供全部源代码、许可证容许买方使用修改开发 | RISK-F02, PARAM-P56 |
| 动态标准 | 以最新标准为准、验收前可修改和调整需求 | RISK-A05, RISK-G03 |
| 背靠背缺失 | 供货商未认可通用册、采购合同未同步罚则与免费义务 | RISK-H02, RISK-H03, RISK-O03 |

> 编号消歧：裸编号 `P02` 在风险类（罚则）与参数类（多屏接口）中都存在，`R05`、`G01` 同理。
> 本表及一切对外引用一律使用 `RISK-` / `QTY-` / `PARAM-` 前缀，消歧规则见 `rules/indexes.md` 附录 A.4。
> 词表仅用于召回提示，命中不等于定性结论；仍须回到对应检查项核对异常判定信号。
