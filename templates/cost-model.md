# 影响分析量化公式库

> 文件：`templates/cost-model.md`
> 职责：为 f6「影响分析」提供可复算的量化口径，避免只写「存在风险」。
> 使用原则：**输入不全时输出区间并标「待核验」，不得编造单价**。
> 关联：`templates/issue-list-template.md` f6；`rules/checkitems-quantity.md`；`rules/checkitems-risk.md` D/H/Q 类。

---

## 1. 通用变量

| 变量 | 含义 | 来源 |
|---|---|---|
| `P_unit` | 设备/软件单价（含税/不含税须注明） | 报价册 / 设备材料表 |
| `Q_dev` | 偏差数量（理论量 − 清单量，取正） | 数量配比核查 |
| `D_days` | 工期延误天数 | 进度计划 / 罚则条款 |
| `R_penalty` | 日罚率（合同价百分比或固定金额） | 罚则条款 |
| `C_contract` | 合同总价 | 合同正文 |
| `T_warranty` | 质保年限 | 质保条款 |
| `R_labor` | 人日费率（含差旅） | 报价册 / 内部标准 |

---

## 2. 公式表

| 场景 | 公式 | 必需输入 | 缺失时处置 |
|---|---|---|---|
| 数量缺口补齐 | `Cost = Q_dev × P_unit × (1 + 安装调试系数)` | `Q_dev`, `P_unit` | `P_unit` 缺失 → 用同类最高单价给上界，标「待核验」 |
| 开口工程量敞口 | `Cost = ΣQ_可能增加 × P_unit` 或 `0.1~0.3 × C_contract`（无明细时） | 清单 / 合同价 | 给区间并注明假设 |
| 罚则暴露 | `Penalty = D_days × R_penalty`，且 `Penalty ≤ Cap` | `D_days`, `R_penalty`, 上限 | 上限未知 → 按合同价 5%~10% 估算并标注 |
| 免费义务折算 | `Cost = Σ(设备 + 软件许可 + 人力 + 差旅 + 检测)` | 各项明细 | 缺项时列明「未计入项」 |
| 长期原价供货 | `Risk = Σ(未来 3 年预计用量 × (市场价 − 合同价))+` | 用量、价差 | 无用量 → 按年用量 = 当前量估算并标注 |
| 源码/许可缺失 | `Cost = 替代开发人日 × R_labor + 许可采购费` | 人日、许可报价 | 无报价 → 只给工作量区间 |
| 验收不通过返工 | `Cost = 返工设备 + 返工人日 × R_labor + 延期罚则` | 返工范围 | 范围不明 → 分「局部返工/整体返工」两档 |
| 备件不足 | `Cost = 年故障率 × 装机量 × P_unit × T_warranty` | 故障率、装机量 | 故障率缺失 → 用 3%~5% 区间并标注 |

> 系数与区间均为**估算默认值**，必须在报告中注明「估算口径」；有项目数据时优先用项目数据。

## 3. 输出写法

```text
影响分析：若按清单数量交付，缺口 10 套冗余 PLC，按报价册单价 ¥4.2 万/套估算，
补齐成本约 ¥42 万（未含安装调试）；若触发日罚 0.5‰×合同价、延误 10 天，
罚则暴露约 ¥XX 万（受罚则上限约束）。
口径：单价来自 BOQ-01 第 3 页；日罚率来自 CON-01 第 12.3 条；工期按总进度计划。
```

要求：

1. 金额给「量级 + 区间」，不要给无依据的精确值。
2. 必须写清「口径」（单价来源、税率、是否含安装）。
3. 无法量化的影响（如验收受阻）写「后果类型 + 触发条件」，不要强行折算金额。
4. 与问题清单 f6、报告第 2 节保持同一数字。

---

## 4. 禁止行为

1. 不得使用模型记忆中的市场价充当项目单价。
2. 不得把估算区间写成确定值。
3. 不得忽略罚则上限、免赔额、责任限额等封顶条款。
4. 不得把「可能」「或许」等模糊词当作量化结论。
